# Работа агентов в Roblox-проекте

## Область и исходники

Эти правила действуют для всего проекта «Гараж странных находок».
Перед работой читай актуальные README.md и default.project.json; описание готовности в README сверяй с кодом.
Сохраняй чужие и ранее существовавшие незакоммиченные изменения.

- src/server → ServerScriptService.GarageServer: авторитетная игровая логика.
- src/client → StarterPlayerScripts.GarageClient: ввод, камера и интерфейс.
- src/shared → ReplicatedStorage.Garage: безопасные общие модули и контракты.
- Код меняется в файлах с последующей синхронизацией Rojo. Не редактируй Source через MCP вместо исходников.

Создание или настройка агентов и Skills само по себе не разрешает менять игру, запускать тесты, Play или публикацию. Действуй по текущей задаче пользователя.

## Роли и Skills

Конфигурации находятся в .codex/agents/. Идентификаторы для поручений:

| Агент | Обязанность | Инструкции Skills |
| --- | --- | --- |
| gameplay_developer | Реализация механик и исправлений в назначенных файлах | roblox-gameplay, roblox-luau; roblox-ui для интерфейса |
| qa_tester | Тестирование и отчёты; без правок игровых исходников | roblox-debug, roblox-gameplay; roblox-ui для интерфейса |
| code_reviewer | Независимое ревью без правок и мутаций Studio | roblox-luau, roblox-debug; roblox-gameplay для правил |

Навыки читай из .agents/skills/<имя>/SKILL.md перед соответствующей работой.
Ролевые ограничения являются инструкциями, а не отдельной технической песочницей.

## Координация

1. Главный агент выступает координатором. Делегируй этим ролям, когда задача требует разработки, независимого ревью или QA; простую правку не обязательно распределять на всех.
2. В поручении укажи цель, критерии готовности, исходный diff/состояние, назначенные файлы, разрешённые действия, допустимые проверки и ожидаемый результат. Отдели изменения задачи от существующих правок.
3. Обычный порядок: Gameplay Developer реализует → Code Reviewer проверяет → Developer исправляет → QA Tester проверяет поведение → координатор подводит результат. При исправлениях повторяй только затронутые проверки.
4. Независимое чтение и подготовка тестовых сценариев могут идти параллельно. У каждого изменяемого файла в один момент только один владелец. Координатор снимает конфликты до редактирования.
5. После передачи ревью/QA зафиксируй проверяемую версию или diff. Если разработчик меняет её во время проверки, сообщи проверяющему и обнови область проверки; старые результаты не считай подтверждением новой версии.
6. Координатор выдаёт исключительный слот на конкретный studio_id для запуска/остановки Play, ввода, симулятора и любых runtime-мутаций. Агенты не переключают общий сеанс параллельно. После работы передай слот и сообщи оставленный режим; не останавливай чужой запуск.
7. При блокировке агент возвращает причину и доступные доказательства координатору. Не отключай защиту и не расширяй задачу ради прохождения проверки.

## Общие требования к реализации и проверкам

- Сервер определяет валюту, владение, награды и переходы состояния. Клиент отправляет намерение.
- Для RemoteEvents сервер проверяет типы, конечность чисел, размеры payload, допустимые ID, права, состояние, расстояние и частоту. Клиентский debounce и типы Luau не являются защитой.
- До оптимизации измеряй проблему; избегай полного обхода дерева каждый кадр, лишних рассылок и неочищенных соединений/задач.
- Перед Studio MCP вызови list_roblox_studios и get_studio_state; выбирай правильный studio_id и доступный Edit/Client/Server.
- Используй существующие StyLua, Selene и TestEZ согласно Skills. scripts/Build.ps1 -Tests может менять test.project.json и сборку: учитывай это до запуска.
- Сетевое поведение проверяй на Server и Client, а взаимодействие игроков — в Server & Clients. Укажи, если такая проверка недоступна.
- Studio Mock не доказывает работу реальных DataStore; эмулятор экрана не подтверждает FPS и память реального телефона.
- Не включай доступ Studio к боевым данным и не публикуй игру без соответствующей задачи пользователя.

## Формат передачи результата

- Developer: изменённые файлы, поведение до/после, проведённые проверки, риски и сценарии QA.
- Reviewer: замечания P0–P3 с файлами/строками, условием возникновения и последствиями; отдельно вопросы и ограничения.
- QA: окружение, проверенная версия, шаги, expected/actual, passed/failed/blocked, доказательства и ограничения.
- Координатор: итог изменений, подтверждённые результаты и оставшиеся проблемы. Не объявляй проверку выполненной без её запуска.
