# Roblox UI

## Контекст проекта и инструменты

- Перед работой прочитай актуальные AGENTS.md, README.md и default.project.json; сохраняй чужие изменения. Здесь src/server → ServerScriptService.GarageServer, src/client → StarterPlayerScripts.GarageClient, src/shared → ReplicatedStorage.Garage. Код редактируется в файлах и синхронизируется Rojo; не подменяй его правкой Source через MCP.
- При использовании Studio MCP сначала вызови list_roblox_studios, выбери нужное место и вызови get_studio_state. Используй фактически возвращённый studio_id, а не сохранённый идентификатор. При неоднозначности уточни цель. Не запускай и не останавливай чужой сеанс без необходимости.
- execute_luau всегда направляй в доступный datamodel_type: Edit для инспекции редактора, Server для серверного состояния, Client для локального UI и ввода. При запросе только на анализ или документацию ограничься чтением; не создавай объекты, не запускай Play и не публикуй игру.
- Проверяй API по официальным страницам ниже. Через MCP можно получить руководство skill с skill_name rbx-docs-search и читать http_get по URL документации с окончанием .md. Недоступность инструмента укажи явно; не выдавай предполагаемый результат за выполненную проверку.

## Порядок работы

1. Найди существующую клиентскую точку входа, создание ScreenGui, Locale и контракт состояния. Сохрани визуальный стиль и язык проекта; не добавляй отдельную систему UI без необходимости.
2. Раздели логику: клиент отображает и отправляет намерения; сервер проверяет доступ, цену и результат. Сервер владеет валютой, инвентарём, наградами, уроном и переходами состояния. Клиент отправляет намерение, а не итоговый баланс или разрешение. В OnServerEvent первый player передаёт движок: не принимай личность игрока из payload. До дорогой работы проверь типы, конечность чисел (NaN/±inf), диапазоны, размеры строк/таблиц, разрешённые ID и принадлежность Instance ожидаемому контейнеру. Затем проверь серверные права, состояние, расстояние и cooldown; применяй серверный лимит частоты на игрока/действие и очищай его при уходе. Не пересылай непроверенный payload другим клиентам. Аннотации типов и клиентский debounce не заменяют runtime-валидацию. Скрытая или отключённая кнопка не является защитой. Закрытые серверные модули не реплицируй ради подписи кнопки.
3. Спроектируй состояния окна: закрыто, загрузка, готово, ожидается ответ, пусто, отказ/ошибка. При отклонении запроса восстанови управление и покажи понятную причину; не показывай успешную покупку до подтверждения сервера. Устаревший ответ не должен перезаписывать новое состояние.
4. Для адаптации используй подходящее сочетание Scale/Offset, AnchorPoint, layout, AutomaticSize и ограничений размеров. Проверь safe area, верхнюю панель Roblox, экранную клавиатуру, прокрутку, длинные RU/EN строки и порядок ZIndex. Учитывай текущий LandscapeSensor из проекта, не меняй ориентацию без задачи.
5. Для кнопок предпочитай GuiButton.Activated; проверь мышь, touch и выбранный gamepad-элемент. Настрой навигацию/возврат фокуса и достаточно крупные зоны нажатия без перекрытия системных кнопок. Подсказки должны соответствовать текущему вводу.
6. Обновляй UI по событиям/изменению данных, а не перестраивай всё дерево каждый кадр. Переиспользуй строки списков, ограничивай длинные списки; отключай подписки и отменяй tween/задачи при закрытии/удалении. Проверь повторное открытие и respawn с фактическим ResetOnSpawn.
7. В Studio на Client проверь несколько размеров экрана через Device Emulator. Для управления симулятором через MCP сначала прочитай skill rbx-device-simulator-lua; для снимков используй только доступный инструмент. Затем проверь серверное подтверждение в Play и изоляцию личного UI в Server & Clients с двумя клиентами.
8. Зафиксируй размеры, способ ввода, язык и результаты. Эмулятор проверяет компоновку и управление; FPS/память мобильного устройства подтверждаются на реальном устройстве, а не по скриншоту Studio.

## Типичные ошибки

- Полностью фиксированная пиксельная компоновка обрезается на другом экране.
- MouseButton1Click и hover становятся единственным способом выполнить действие.
- Каждое открытие подключает ещё один обработчик Activated и отправляет дубли remotes.
- Локальный баланс считается истинным; кнопка «недоступна» только визуально.
- Короткий английский текст проверен, русский обрезан; игровой ввод работает сквозь модальное окно.

## Критерии проверки

- Ключевые элементы доступны на выбранных размерах, текст читаем, прокрутка/фокус работают с нужными видами ввода.
- Загрузка, отказ, повторный клик и запоздавший ответ не приводят к ложному успеху или зависшей кнопке.
- Личный UI не появляется у другого игрока; сервер отклоняет запрещённый запрос независимо от интерфейса.
- Повторное открытие/respawn не умножают подписки и запросы; обновления UI не вызывают заметных всплесков frame time.
- В итоговом отчёте перечисли изменённые файлы, выполненные проверки с результатами и оставшиеся ограничения. Различай статический анализ, одиночный Play, Server & Clients и реальное устройство.
- Для изменений кода используй существующие StyLua/Selene и TestEZ. scripts/Build.ps1 -Tests также создаёт сборку и может обновить test.project.json: сначала проверь его актуальное содержимое и необходимость перезаписи. В отдельной тестовой сборке, где существует ServerStorage.GarageTests, серверный запуск: return require(game.ServerStorage.GarageTests.Run)(). Ноль выполненных тестов не считается успехом. На этапе создания навыков эти проверки игры не запускай.
